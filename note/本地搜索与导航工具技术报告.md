# 本地搜索与导航工具技术报告

> 对应 commit `7420944`：新增 `glob` / `grep` / `ls` 三个本地代码库搜索导航工具。
> 本文记录这次实现的设计动机、工具接口、关键实现细节和验证方式。

---

## 背景

之前 cb-agent 虽然已经有 `bash` 和 `my_advanced_search`：

- `my_advanced_search` 负责互联网搜索，不适合查本地代码。
- `bash` 可以执行 `rg` / `find` / `dir` 等命令，但模型需要自己拼 shell 命令，容易遇到平台差异、权限弹窗、输出过大、路径状态不一致等问题。
- `file_read` 能精确读取已知文件，但不能帮助模型先定位“有哪些文件”或“哪个文件包含某段代码”。

因此本次补齐 Claude Code 风格的本地搜索与导航能力，把常见代码库探索动作拆成三个专用只读工具：

| 工具 | 搜索维度 | 典型问题 |
|---|---|---|
| `glob` | 按文件名 / 通配符找文件 | “所有测试文件在哪” |
| `grep` | 按文件内容 / 正则找代码 | “这个函数在哪里定义/调用” |
| `ls` | 浏览目录结构 | “先看一下项目布局” |

核心目标是让模型少走 `bash`，优先通过结构化工具完成搜索导航。

---

## 顶层方案

新增文件：`tools/tools/local_search.py`

该文件同时包含：

1. 三个 Tool 子类：`GlobTool`、`GrepTool`、`LsTool`
2. 公共路径解析逻辑
3. 默认忽略目录规则
4. ripgrep 调用封装
5. Python 降级搜索实现
6. 结果分页、截断、mtime 排序和相对路径格式化

工具注册位置在 `run_agent.py` 的 `_register_native_tools()`：

```python
SearchTool(),
GlobTool(),
GrepTool(),
LsTool(),
BashTool(...),
FileReadTool(),
```

这样保留原来的 Web 搜索工具，同时把本地搜索工具作为独立原生工具注册进 `ToolRegistry`。

## 工具接口

### `glob`

用途：按文件名通配符查找文件。

参数：

| 参数 | 必填 | 默认 | 说明 |
|---|---:|---|---|
| `pattern` | 是 | - | glob pattern，例如 `**/*.py`、`src/**/*.ts` |
| `path` | 否 | 当前 cwd | 搜索目录 |
| `limit` | 否 | `100` | 最大返回文件数 |

返回 JSON 字段：

- `path`：实际搜索目录
- `backend`：`rg` 或 `python`
- `duration_ms`：耗时
- `truncated`：是否截断
- `files`：匹配文件列表
- `num_files`：本次返回数量
- `total_matches`：截断前匹配总量

结果按文件修改时间从新到旧排序。这个设计假设“最近改动的文件更可能与当前任务相关”，能让模型优先看到活跃代码。

### `grep`

用途：按正则搜索文件内容。

参数：

| 参数 | 必填 | 默认 | 说明 |
|---|---:|---|---|
| `pattern` | 是 | - | 正则表达式 |
| `path` | 否 | 当前 cwd | 搜索文件或目录 |
| `glob` | 否 | - | 文件过滤，例如 `*.py`、`**/*.tsx` |
| `output_mode` | 否 | `files_with_matches` | `files_with_matches` / `content` / `count` |
| `head_limit` | 否 | `250` | 最大返回条目数，`0` 表示不限量 |
| `offset` | 否 | `0` | 跳过前 N 条结果，用于分页 |
| `case_insensitive` | 否 | `false` | 是否忽略大小写 |
| `context` | 否 | `0` | content 模式下前后上下文行数 |
| `multiline` | 否 | `false` | 是否启用跨行正则 |

三种输出模式：

| 模式 | 返回重点 |
|---|---|
| `files_with_matches` | 只返回包含匹配的文件路径，适合先缩小范围 |
| `content` | 返回匹配行，带文件名和行号，适合直接定位代码 |
| `count` | 返回每个文件的匹配次数，适合看分布 |

返回 JSON 字段：

- `mode`
- `files`
- `content`
- `num_files`
- `num_matches`
- `applied_limit`
- `applied_offset`
- `truncated`
- `backend`
- `duration_ms`

### `ls`

用途：浏览目录结构。

参数：

| 参数 | 必填 | 默认 | 说明 |
|---|---:|---|---|
| `path` | 否 | 当前 cwd | 要浏览的目录 |
| `depth` | 否 | `1` | 递归深度 |
| `limit` | 否 | `200` | 最大返回条目数 |
| `include_hidden` | 否 | `false` | 是否展示隐藏文件/目录 |

返回 JSON 字段：

- `path`
- `duration_ms`
- `truncated`
- `entries`
- `total_entries`

`entries` 使用紧凑路径列表，目录以 `/` 结尾，便于模型继续调用 `glob` / `grep` / `file_read`。

## 路径与忽略规则

### 相对路径基准

三个工具都复用与 `file_read` 一致的路径语义：

- 绝对路径：原样使用
- 相对路径：基于 `tools.tools.bash_session.get_session().cwd`

这保证模型通过 `bash` 执行 `cd` 后，再调用 `glob` / `grep` / `ls` 时仍然在同一个工作目录视角里。

### 输出路径格式

返回给模型的文件路径尽量相对当前 cwd：

```text
src/app.py
test/test_local_search_tools.py
```

只有路径不在当前 cwd 下时，才返回绝对路径。这样能节省 token，也更适合后续直接传给 `file_read`。

### 默认忽略目录

默认排除：

```text
.git .svn .hg .bzr .jj .sl
node_modules .venv venv __pycache__
.pytest_cache .mypy_cache .ruff_cache
dist build
```

这些目录要么是版本控制元数据，要么是依赖/缓存/构建产物。默认忽略它们可以避免搜索结果被噪声淹没。

## ripgrep 与 Python 降级

### 优先使用系统 `rg`

实现通过 `shutil.which("rg")` 检测系统 ripgrep：

- 有 `rg`：使用 `subprocess.run()` 调用
- 无 `rg`：进入 Python 降级路径

没有引入 Claude Code 的内嵌 ripgrep/vendor 分发，原因是 cb-agent 当前仍以轻量 Python 项目为主，先保持依赖简单。

### `glob` 的 rg 调用

核心参数：

```text
rg --files --hidden --glob <pattern> --glob !.git/** ...
```

`--files` 只列出文件，不搜索内容。随后 Python 层按 mtime 排序并截断。

### `grep` 的 rg 调用

公共参数：

```text
rg --hidden --max-columns 500
```

关键细节：

| 情况 | 处理 |
|---|---|
| pattern 以 `-` 开头 | 使用 `-e <pattern>`，避免被 rg 当成命令参数 |
| 单文件 content/count 搜索 | 强制 `--with-filename`，保证输出仍带路径 |
| count 模式 | 使用 `--count-matches`，统计匹配次数而不是匹配行数 |
| content 模式 | 默认 `-n` 输出行号 |
| context > 0 | 追加 `-C <context>` |
| multiline=true | 追加 `-U --multiline-dotall` |

### Python 降级路径

Python 降级路径主要负责兜底可用性：

- 使用 `os.walk()` 遍历目录
- 原地裁剪忽略目录，避免递归进入噪声目录
- 使用 `fnmatch` 处理 glob
- 使用 `re` 处理内容搜索
- 用 `Path.read_text(errors="replace")` 容忍非标准编码文本

降级路径并不追求完全复刻 ripgrep 的所有正则和 glob 语义，但会保持返回 JSON 形状一致。

## 并发与 Bash 提示调整

### 只读并发

`agent/executor.py` 的 `READ_ONLY_TOOLS` 新增：

```python
"glob",
"grep",
"ls",
```

因此同一轮模型如果同时发起多个本地搜索/读取工具调用，执行器可以用线程池并发执行。

### BashTool 描述调整

`tools/tools/bash_tool.py` 的描述增加提醒：

```text
代码搜索和目录浏览请优先使用 grep/glob/ls 专用工具，只有专用工具无法满足时再用 bash。
```

这能降低模型通过 `bash` 拼搜索命令的概率，减少平台差异和权限弹窗。

## 测试覆盖

新增测试文件：`test/test_local_search_tools.py`

覆盖场景：

1. `glob` 能按 `**/*.py` 找文件，并按 mtime 从新到旧排序
2. `glob` 在无 `rg` 时走 Python 降级
3. `grep files_with_matches` 支持 glob 过滤和大小写忽略
4. `grep content` 支持 `head_limit` / `offset` 分页
5. `grep count` 统计匹配次数，同一行多次匹配会累计
6. `grep` 搜索 `--force` 这类以短横线开头的 pattern 不会被当成参数
7. `grep` Python 降级返回与 rg 路径一致的内容形状
8. `ls` 遵守 `depth` 和 `include_hidden`
9. `ls` 命中 `limit` 时返回 `truncated=true`

同时更新 `test/test_executor.py`：

- 确认 `glob` / `grep` / `ls` 在只读白名单中
- 确认它们能与 `file_read` / `search` / `memory_search` 一起触发并发执行

验证命令：

```powershell
python test\test_local_search_tools.py
$env:PYTHONPATH='.'; python test\test_executor.py
python -m unittest discover -s test -p "test_local_search_tools.py"
python -m unittest discover -s test -p "test_executor.py"
python -m py_compile tools\tools\local_search.py run_agent.py agent\executor.py tools\tools\bash_tool.py test\test_local_search_tools.py test\test_executor.py
```

注意：仓库根目录存在历史文件 `test.py`，直接运行 `python -m unittest test.test_local_search_tools` 会被这个文件抢占模块名，因此推荐使用 discover 或直接执行测试文件。

## 后续可扩展点

1. **内嵌 ripgrep**：如果未来要做完整跨平台打包，可以参考 Claude Code 的 vendor/embedded ripgrep 策略，避免依赖系统 `rg`。
2. **更完整的 `.gitignore` 支持**：当前 Python 降级只使用内置忽略目录，没有解析项目 `.gitignore`。
3. **WebFetch 工具**：本次只补本地搜索导航；网页抓取和 Markdown 转换可以后续单独实现 `web_fetch`。
4. **更细的 UI 展示**：当前返回 JSON 给模型和前端，未来可为 `glob` / `grep` / `ls` 增加 `__display__`，让 TUI 工具卡片更清爽。
