## 1. 协议

```text
用户消息 = text + attachments[]
```

- **唯一模型输入**（`request_content`）：可含原生 `image_url` data URI、OCR/ASR 摘要、文档 Markdown 的 **manifest + 聚合预算内 preview**。
- **跨轮持久化**（canonical history / `history.jsonl`）：原样保存模型实际看见的 `request_content`，不会在下一轮把 data URI 换成 filepath 或摘要。文本/文档仍只注入 manifest + preview，不保存完整 120K Markdown 正文。

## 2. 文本/文档 artifact

转换后的完整 Markdown（或 OCR/ASR 全文）写入：

```text
.cbagent/attachments/<content_hash>/content.md
```

模型请求与 canonical history 只注入：

- 文件名、原始 path、modality、hash、size
- artifact 路径与 `full_chars` / `preview_chars`
- 聚合预算内的 preview
- `file_read` 分页续读提示

`ProcessedAttachment` 字段：`artifact_path`、`full_chars`、`preview_chars`、`text`（preview 或摘要）、`routed_as`。

## 3. 聚合预算

| 常量 | 含义 |
|------|------|
| `DEFAULT_ATTACHMENT_TEXT_MAX_CHARS` | 默认合计 preview 预算（env `CBAGENT_ATTACHMENT_TEXT_MAX_CHARS` 可覆盖；语义是**合计**不是单文件 120K） |
| soft_limit 比例 | 约 `soft_limit_tokens * 4 * 0.08`，再夹在 min/max |
| 用户正文 | 先从预算中扣除 |

多附件时按顺序消耗 `remaining_preview_budget`；预算用尽仍生成 manifest，preview 可为空并提示读 artifact。

原生视觉图片另有三层聚合保护：附件数量上限、单文件大小/像素尺寸校验、按图片尺寸估算的视觉 token 总预算。视觉 token 与文本 preview 一起受当前模型 soft limit 约束，不能因 data URI 在普通文本估算中被净化就漏算图片成本。

## 4. 路由

| 模态 | 条件 | 请求与 canonical history |
|------|------|--------------------------|
| image | 模型支持视觉 | `image_url` data URI |
| image | 纯文本模型 | OCR → artifact + preview |
| audio | 始终 | ASR → artifact + preview |
| text/document | MarkItDown 或纯文本解码 | 全文 artifact + preview |

`sanitize_multimodal_payload`：token 估算、日志、dump 时把 data URI 换成占位符，**不修改**真正发给模型或保存在 canonical history 中的消息。

视觉能力优先读取当前 `ModelChoice` 绑定的 `ActiveModelConfig.image_ability`，只在没有 active config 时兼容旧 model id 查询。同名 model id 位于不同 provider 时不得串用能力配置。

## 5. 失败语义

- 路径不存在、格式不支持、超 `CBAGENT_ATTACHMENT_MAX_MB` → `MultimodalInputError`，请求失败。
- 转换失败 / artifact 写盘失败 → 明确错误，不伪造成功。
- 小窗口 + 大附件：靠 preview 预算限制，**不**靠 compact 历史来“消化”当前输入超窗。
- mid-turn compact 后，当前活动回合（含原生图片）整体原样保留在 replacement history，不再经过 request-only 回挂支线。

## 6. 与 file_read / bash 的关系

附件全文与 bash 大输出都落盘后，用 `file_read` 的 head/range/char_range/`byte_range` 流式分页续读；continuation cursor 保证无重复、无整文件 `read_text`。
