# 多模态输入与上下文管理技术报告

> 对应本次更新：为 cb-agent 增加统一附件协议、图片/音频输入路由、TUI 剪贴板图片入口，以及长期上下文脱敏策略。

---

## 背景

之前 cb-agent 的用户输入只有纯文本。虽然仓库里已经有 `utils/multimodal.py`，可以通过外部 OCR/ASR 模型把图片、音频转成文本，但主会话链路并不知道“用户消息还带了附件”：

- TUI/CLI 没有附件队列。
- JSON-RPC `prompt.submit` 只能提交 `{text}`。
- `AgentSession.history` 只能按普通用户文本保存。
- 多模态基模和纯文本基模没有分流策略。
- 如果直接把图片 base64 写入 history 或 message log，会撑爆上下文，也会污染本地持久化。

因此本次引入统一协议：

```text
用户消息 = text + attachments[]
```

首版支持图片和音频。文件二进制只在当前轮必要时进入模型请求，跨轮上下文只保留文本摘要与附件元数据。

---

## 顶层方案

### 新增后端处理层

新增文件：

```text
agent/multimodal_input.py
```

核心职责：

1. 校验附件路径、格式、大小。
2. 识别 `image` / `audio` 模态和 MIME。
3. 根据当前主模型能力决定图片路由。
4. 调用 `utils.multimodal.MultimodalProcessor` 执行 OCR/ASR。
5. 生成两份内容：
   - `request_content`：当前轮发给 LLM 的 OpenAI-compatible user content。
   - `history_text`：写入 history/transcript/compact 的纯文本摘要。

### 扩展消息入口

`AgentSession.chat()` / `chat_async()` 增加参数：

```python
attachments: Optional[List[Dict[str, Any]]] = None
```

JSON-RPC `prompt.submit` 从：

```json
{"text": "hello"}
```

扩展为：

```json
{
  "text": "这张图里有什么？",
  "attachments": [
    {
      "path": "C:\\Users\\cb135\\Desktop\\shot.png",
      "modality": "image",
      "source": "direct"
    }
  ]
}
```

旧的 `{text}` 协议继续可用。

### 扩展前端入口

CLI：

- `/attach <path>` 添加本地附件。
- `/attachments` 查看队列。
- `/detach <index|all>` 移除附件。

TUI：

- `/attach <path>` 添加本地附件。
- `/paste-image` 从系统剪贴板读取图片并加入附件队列。
- `Ctrl-V` 也会尝试读取剪贴板图片，但很多终端会拦截该快捷键，因此 `/paste-image` 是更可靠入口。
- `/attachments` 查看队列。
- `/detach <index|all>` 移除附件。

## 模型能力判断

当前是否支持图片输入，由 `ConstantLLM.llm_dict[model]["image_ability"]` 决定。

示例：

```python
"mimo-v2.5-pro": {
    "is_tool": True,
    "is_reasoning": True,
    "json_output": True,
    "max_tokens": 1000000,
    "image_ability": True,
}
```

判断函数在 `agent/multimodal_input.py`：

```python
def model_supports_image(model: Optional[str]) -> bool:
    config = ConstantLLM.llm_dict.get(str(model or ""))
    return bool(config.get("image_ability")) if isinstance(config, dict) else False
```

这是一种显式配置策略，不做运行时 API 探测。优点是稳定、可审计；代价是新增模型时必须正确登记能力字段。

## 附件路由

### 图片 + 多模态主模型

当：

```python
image_ability == True
```

后端读取图片文件，把它转成当前轮 OpenAI-compatible content part：

```json
{
  "type": "image_url",
  "image_url": {
    "url": "data:image/png;base64,..."
  }
}
```

同时插入一段短文本说明，告诉模型本轮包含附件。说明中只包含文件名，不包含本机绝对路径。

跨轮 history 保存：

```text
[附件摘要 #1] modality=image file=shot.png source=direct routed_as=image_url size=... hash=...
图片已原生发送给支持视觉输入的模型。
```

### 图片 + 纯文本主模型

当：

```python
image_ability == False
```

后端调用：

```python
MultimodalProcessor.process_image(path)
```

得到 OCR/视觉描述文本后，把文本作为普通 text content 发给主模型：

```text
[附件 #1: image shot.png]
这里是 OCR/视觉描述结果...
```

如果 OCR 未配置或返回空文本，本轮会返回明确错误，不会静默忽略附件。

### 音频

音频首版不做主模型原生音频输入，统一调用：

```python
MultimodalProcessor.process_audio(path)
```

得到 ASR 转写文本后发给主模型。

如果 ASR 未配置或返回空文本，本轮会返回明确错误。

## TUI 剪贴板图片链路

TUI 不通过 JSON-RPC 直接传图片二进制。

`/paste-image` 或可用时的 `Ctrl-V` 流程：

1. TUI 调用 `readClipboardImageAttachment()`。
2. 根据平台读取系统剪贴板图片：
   - Windows：PowerShell `-STA` + `.NET Clipboard`
   - macOS：`pngpaste`
   - Linux：`wl-paste` 或 `xclip`
3. 图片保存为本地文件：

```text
~/.cb-agent/attachments/clipboard-<timestamp>-<seq>.png
```

4. TUI 把附件对象加入队列：

```json
{
  "path": "C:\\Users\\cb135\\.cb-agent\\attachments\\clipboard-xxx.png",
  "modality": "image",
  "source": "clipboard"
}
```

5. 用户发送下一条消息时，`Transport.sendPrompt(text, attachments)` 发送 JSON-RPC：

```json
{
  "method": "prompt.submit",
  "params": {
    "text": "图里有什么？",
    "attachments": [
      {
        "path": "...clipboard-xxx.png",
        "modality": "image",
        "source": "clipboard"
      }
    ]
  }
}
```

6. 后端收到 ack 后，TUI 清空附件队列。

这样做的好处：

- JSON-RPC 不承载大块 base64，协议保持轻量。
- 后端可以统一按路径重新校验和处理。
- 剪贴板图片有可审计的临时文件来源。

## 上下文管理与隐私边界

本次实现的关键原则：

```text
当前轮可以携带 data URI；跨轮只能保存文本摘要和元数据。
```

为此分离了两份内容：

| 内容 | 用途 | 是否可包含 data URI |
|---|---|---|
| `request_content` | 当前轮 LLM 请求 | 可以，仅多模态图片原生路由时 |
| `history_text` | history / transcript / compact / context_window_usage | 不可以 |

### history

`AgentSession` 保存用户消息时使用：

```python
Message.create_user_message(history_user_text)
```

而不是保存本轮的 `request_content`。

### transcript/state/compact

`_persist_turn()`、`_make_work_record()`、`context_window_usage()` 都基于 `history_user_text` 或跨轮文本状态工作，不会拿到图片 data URI。

### token 估算和消息日志

新增：

```python
sanitize_multimodal_payload()
```

它会把：

```text
data:image/png;base64,...
```

替换成：

```text
[data-uri omitted: image/png, chars=...]
```

目前用于：

- `_estimate_request_tokens()`
- CLI `/msg` messages dump
- `MessageLogger`

这样即使 `CBAGENT_LOG_LEVEL=full`，也不会把图片 base64 写入 messages 日志。

## 路径语义

附件路径解析与现有文件工具保持一致：

- 绝对路径原样使用。
- 相对路径基于当前 `BashSession.cwd`。

这意味着用户通过 bash 工具 `cd` 到某个目录后：

```text
/attach ./shot.png
```

会和：

```text
file_read(path="./shot.png")
```

使用同一个路径基准。

TUI 侧可能无法预先 `stat` 到相对路径，因为真正的基准在 Python 后端的 `BashSession.cwd`。因此 TUI 只做展示级元数据，最终校验仍在后端。

## 支持格式与限制

图片：

```text
png, jpg, jpeg, webp, gif, bmp, tiff, tif
```

音频：

```text
mp3, wav, m4a, aac, flac, ogg, wma
```

单文件大小限制：

```env
CBAGENT_ATTACHMENT_MAX_MB=20
```

默认 20 MB。配置错误时回退默认值。

## 错误处理

后端会对以下情况返回明确错误：

- `attachments` 不是对象数组。
- 没有文本也没有附件。
- 附件路径为空。
- 文件不存在或不是普通文件。
- 扩展名不支持。
- `modality` 与扩展名不匹配。
- 文件超过大小限制。
- OCR/ASR 未配置或返回空文本。

这些错误不会静默吞掉附件，避免模型在没看到图片/音频的情况下假装回答。

```bash

python -m unittest discover -s test -p "test_multimodal_input.py"
python -m unittest discover -s test -p "test_session_renderer.py"

```

## 后续可扩展点

1. 在 prompt 中加入安全相对路径，方便模型引用附件来源，但不暴露本机绝对路径。
2. 支持 WebUI 文件上传，复用同一 `{text, attachments}` 协议。
3. 为 OCR/ASR 加缓存，避免同一附件重复转写。
4. 对视频、PDF、Office 文档增加新的 modality 或独立工具链。
5. 为多模态 provider 差异增加 adapter，支持非 OpenAI-compatible 的图片输入格式。
