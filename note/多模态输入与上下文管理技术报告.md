# 多模态输入与上下文管理技术报告

> 更新于 2026-07-23。以 `agent/multimodal_input.py` 为准。旧文中「单附件固定 120K 整文注入 history」已作废。

## 1. 协议

```text
用户消息 = text + attachments[]
```

- **当前轮请求**（`request_content`）：可含原生 `image_url` data URI、OCR/ASR 摘要、文档 Markdown 的 **manifest + 聚合预算内 preview**。
- **跨轮持久化**（`history_text` / transcript / compact）：只保留用户原文 + 附件 manifest/短 preview；**禁止** base64 与完整 120K Markdown 正文。

## 2. 文本/文档 artifact

转换后的完整 Markdown（或 OCR/ASR 全文）写入：

```text
.cbagent/attachments/<content_hash>/content.md
```

请求与 history 只注入：

- 文件名、原始 path、modality、hash、size
- artifact 路径与 `full_chars` / `preview_chars`
- 聚合预算内的 preview
- `file_read` 分页续读提示

`ProcessedAttachment` 字段：`artifact_path`、`full_chars`、`preview_chars`、`text`（preview 或摘要）、`routed_as`。

## 3. 聚合预算

| 常量 | 含义 |
|------|------|
| `DEFAULT_ATTACHMENT_TEXT_MAX_CHARS` | 默认合计 preview 预算（env `CBAGENT_ATTACHMENT_TEXT_MAX_CHARS` 可覆盖；语义是**合计**不是单文件 120K） |
| soft_limit 比例 | 约 `soft_limit_tokens * 4 * 0.08`，再夹在 min/max |
| 用户正文 | 先从预算中扣除 |

多附件时按顺序消耗 `remaining_preview_budget`；预算用尽仍生成 manifest，preview 可为空并提示读 artifact。

## 4. 路由

| 模态 | 条件 | 请求 | history |
|------|------|------|---------|
| image | 模型支持视觉 | `image_url` data URI | 短摘要，无 base64 |
| image | 纯文本模型 | OCR → artifact + preview | manifest + 短 preview |
| audio | 始终 | ASR → artifact + preview | 同上 |
| text/document | MarkItDown 或纯文本解码 | 全文 artifact + preview | 同上 |

`sanitize_multimodal_payload`：token 估算、日志、dump 时把 data URI 换成占位符，**不修改**真正发给模型的 messages。

## 5. 失败语义

- 路径不存在、格式不支持、超 `CBAGENT_ATTACHMENT_MAX_MB` → `MultimodalInputError`，请求失败。
- 转换失败 / artifact 写盘失败 → 明确错误，不伪造成功。
- 小窗口 + 大附件：靠 preview 预算限制，**不**靠 compact 历史来“消化”当前输入超窗。

## 6. 与 file_read / bash 的关系

附件全文与 bash 大输出都落盘后，用 `file_read` 的 head/range/char_range/`byte_range` 流式分页续读；continuation cursor 保证无重复、无整文件 `read_text`。
