# 通讯平台敏感权限与临时产物发送技术报告

## 背景

QQ/NapCat 接入后，agent 的调用者不再一定是本机用户。私聊好友、群友、未来微信用户都可以通过通讯软件触发模型和工具。如果所有工具都按本地 TUI/CLI 的信任边界处理，就会出现几个风险：

- 普通群友让 agent 读取项目源码、日志、配置、token、环境变量；
- 普通用户让 agent 执行 git 回滚、提交、推送、写文件、修改记忆；
- 普通用户让 agent 发送服务器本地文件到 QQ；
- 用户先让 agent 把敏感文件复制到临时目录，再通过文件发送工具绕过限制。

本次更新增加通讯平台专用的身份与权限层。它只在 QQ/未来微信等通讯平台上下文中生效，不改变本地 CLI/TUI 原有行为。

## 身份来源

QQ 适配器在处理入站消息时，会把当前会话和发送者 QQ 号写入 `ContextVar`：

- `ConversationKey(platform="qq", kind="private|group", id="...")`
- `sender_id=<QQ号>`

工具执行层会复制这些 `ContextVar` 到工具线程，所以即使工具并发执行，也能知道“是谁触发了这次工具调用”。

同时，`InboundMessage.prompt_text()` 会在当前轮用户文本头部注入 `sender_id`：

```text
[通讯软件消息 platform=qq conversation=private:2978048948 sender_id=2978048948 sender=cb]
```

这个头部只服务当前轮推理，不写入长期 `history/transcript/state`。长期持久化仍只保存用户原始文本，避免每轮都把平台元数据刷进上下文。

## root 用户配置

通讯平台 root 用户通过环境变量配置：

```env
QQ_ROOT_USERS=10001,10002
IM_ROOT_USERS=wxid_xxx,10003
```

判定规则：

- QQ 模式同时检查 `QQ_ROOT_USERS` 和 `IM_ROOT_USERS`；
- 未来微信/Telegram 等平台可复用 `IM_ROOT_USERS`；
- 未配置 root 用户时，通讯平台敏感工具默认拒绝；
- `QQ_ALLOWED_USERS` 只决定谁能和 agent 聊天，不代表谁能执行敏感工具。

这让“能使用 agent”和“能操作服务器/项目”分成两层权限。

## 工具硬拦截

权限检查位于 `ToolExecutor._run_one()`，在 `ToolStart` 事件发出和真实工具执行之前。这样被拒绝的敏感工具不会真的运行，也不会在 QQ 中显示“工具已开始执行”的假信号。

普通通讯用户默认禁止：

- `file_read`，因为它会读取并外发本地文件内容；
- `file_write` / `file_edit` 写项目或服务器文件；
- `grep(output_mode=content)` 外发匹配正文；
- 非只读 `bash`；
- `cat`、`head`、`tail`、`rg`、`grep`、`Get-Content`、`git diff`、`git show` 等会外发本地文件内容的 bash 命令；
- `bash_task output/wait/kill`；
- `bash_permission grant/revoke`；
- `memory/rag` 写操作；
- 执行 Skill 脚本的 `bash` 命令，按 bash 敏感命令规则统一拦截；
- 发送项目/服务器本地文件；
- 默认敏感 MCP 前缀，例如 `github_`、`playwright_`。

普通通讯用户仍可使用：

- 普通问答；
- Web 搜索和 fetch/tavily/amap 查询类 MCP；
- `glob`、`ls`、`grep(files_with_matches/count)` 等不外发正文的本地导航；
- `git status` 等只读状态命令；
- 通过 `sticker_name` 发送表情包目录里的表情包。

## 临时产物例外

通讯软件聊天中，经常会有合理需求：

- “帮我生成一个 PDF 发给我”；
- “下载这张公网图片发到 QQ”；
- “生成一个报告文件给我”。

如果一刀切禁止普通用户发送任何 `path`，这些能力都会失效。因此本次加入一个窄例外：

普通通讯用户可以把“本次为用户新生成/新下载的产物”放到系统临时目录，再用 `send_message_asset(path=...)` 发送。

推荐目录：

```text
/tmp/cb-agent-outputs/
```

Windows 上使用 `tempfile.gettempdir()` 对应的系统临时目录。

允许的动作：

- `file_write` / `file_edit` 写入临时目录中的新产物；
- `send_message_asset(path=...)` 发送临时目录中的文件；
- `curl` / `wget` 从公网 `http(s)` URL 明确下载到临时目录。

仍然拒绝的动作：

- 把项目源码、配置、日志、密钥、服务器隐私文件复制或移动到临时目录后发送；
- 通过临时目录软链接指向项目目录后发送；
- 使用 `file://`、localhost、内网地址、链路本地地址下载；
- 使用 `curl -L` 或其他自动重定向选项，因为静态权限检查无法确认重定向目标是否跳到内网；
- 管道远程脚本到 shell。

路径检查使用 `Path.resolve(strict=False)` 解析最终真实路径。已有软链接父目录会被展开，因此 `/tmp/link -> /root/CBAGENT/cb-agent` 这类绕过不会被误判为安全临时产物。

## NapCat Docker 文件交付

临时产物目录和 NapCat 共享目录是两个不同概念：

- `/tmp/cb-agent-outputs/`：权限层认可的“普通用户新产物输出区”；
- `QQ_FILE_HOST_PREFIX`：NapCat Docker 能看到的宿主机共享目录。

在 `QQ_FILE_DELIVERY_MODE=mapped_path` 下，交付层会自动复制文件：

```text
agent 生成 /tmp/cb-agent-outputs/a.pdf
send_message_asset 权限检查通过
QQFileDeliveryManager 复制到 QQ_FILE_HOST_PREFIX
路径改写成 QQ_FILE_NAPCAT_PREFIX 下的容器路径
NapCat 使用容器内路径发送文件
```

实现位置是 `agent/qq/file_delivery.py` 的 `_build_mapped_path_candidate()`，使用 `shutil.copy2(source, target)`。这是复制，不是移动，源文件仍保留在临时目录。

推荐配置：

```env
QQ_FILE_DELIVERY_MODE=mapped_path
QQ_FILE_HOST_PREFIX=/root/CBAGENT/cb-agent/outbound
QQ_FILE_NAPCAT_PREFIX=/app/cb-agent-outbound
```

NapCat Docker 挂载：

```bash
-v /root/CBAGENT/cb-agent/outbound:/app/cb-agent-outbound:ro
```

这样不需要把 `/tmp/cb-agent-outputs/` 直接挂载给 NapCat。临时目录负责权限边界，共享目录负责 Docker 文件可见性。

## 系统提示词约束

通讯平台模式会额外注入一段提示词，说明：

- 当前会话来自通讯平台；
- 用户文本头部的 `sender_id` 是平台身份来源；
- 只有 `QQ_ROOT_USERS` / `IM_ROOT_USERS` 配置的账号是 root；
- 普通用户请求服务器隐私、源码、token、配置、日志时要拒绝；
- 生成/下载/制作的回传文件应写入 `/tmp/cb-agent-outputs/` 或系统临时目录；
- 不得把本地敏感文件复制到 `/tmp` 后发送。

这段提示词只在 `communication_platform` 存在时追加。CLI/TUI 不会看到这些通讯平台专用约束，避免污染本地交互体验和系统提示词缓存前缀。
