# 跨轮工作上下文技术报告

> 更新于 2026-07-26。以当前 `agent/session.py`、`agent/work_context.py`、`context/world_state.py` 为准。

## 1. 分层数据

| 层 | 存什么 | 进模型？ | 跨进程？ |
|----|--------|----------|----------|
| **active history** | 完整协议消息（user / assistant / tool / context_update / compaction summary） | 是 | transcript + compact 恢复 |
| **transcript** | 每轮提交的审计流（含坏行 salvage、turn_seq cursor） | 否（恢复后才进 history） | 是 |
| **state.json** | 文件/命令/决策/待办等 UI 与人工审计 | **默认否** | 是 |
| **world state baseline** | 已告知模型的 durable section 规范值 | 仅增量 diff | compact / history 中的 context_update |
| **request-only** | knowledge、runtime_instructions、raw_environment 等 | 仅本轮请求 | 可选 ephemeral 审计，**不**还原为模型消息 |
| **artifact** | bash/附件/工具大输出全文 | 否（用 file_read 分页） | 磁盘 |

**禁止**：按 `history_window` / `max_messages` 裁剪 active history。超窗只走正式 compact。

## 2. 一次请求的构造顺序

```text
稳定 system（静态 + 可选 addendum）
完整 active history（append-only 协议消息）
持久 section 增量 context_update（可能为空）
本轮 request-only context（RAG / hook / subagent 等）
当前用户消息（及附件 manifest/preview）
```

回合成功后只提交：

```text
持久 section 增量 context_update（若有）
用户消息
assistant / tool 协议链
```

request-only **不**进入 active history。下一轮允许最近动态尾部 cache miss，但共同前缀至少是 `system + durable_history_N`。

## 3. World state 与三态 section

- `DynamicSectionResult`：`present` / `absent` / `error`。
- `context/prompts/builder.py` 直接返回 `DynamicSectionResult`；Session 不再根据 section 名维护第二套隐式 persistence 白名单。
- **error**：状态未知，**不**发 `removed`，保留 baseline。
- **persistent**：进入 history 的 context_update，参与 baseline diff。
- **request_only**：仅本轮，不进 baseline。
- 首次构建 `instructions` 失败且没有旧 baseline 可沿用时，必须阻止模型请求；不能把关键指令读取失败伪装成 absent。

`session_state` 默认不注入模型；完整 history 已含原始工具事实。仅 recovery / 迁移 / 显式诊断可生成一次性 `recovery_context`（标注来源）。

旧版 context_update 中的 Plan Mode 文本只允许在 `load_latest_history()` 迁移边界规范化。正常请求组装只读取完整 active history，不得每轮用正则重写旧消息。

## 4. 持久化与恢复

### 4.1 transcript

- 合法 JSONL 行 salvage；坏行不拖垮后续。
- compact v3：`transcript_cursor_seq`（turn_seq）。
- compact v2：`transcript_offset` = 当时**非空物理行**序号，坏行也占位，禁止按“有效 records 下标”切片。

### 4.2 load_latest_history

- **无** `max_messages` 生产参数；始终恢复完整可恢复 history。
- 叠加 compact replacement + cursor 后 transcript + active_turn/pending 去重。
- 恢复后对孤儿 tool 做 `drop_orphan_tool_message_objects`（**存储损坏防御**，日志 error）。

### 4.3 pending / active_turn

- 失败的 provider 调用不得 `append_turn`。
- active 与 pending 按 turn_id 去重；已 committed 的 turn 不重复注入。

## 5. 模型配置真相

- 运行时 limits / 能力绑定 **ModelChoice.key**（provider + model + 窗口），不写回全局 `llm_dict` 同名键。
- 模型切换是明确 cache boundary。

## 6. 与 compact / 工具的接口

- 工具结果：executor `result_cap` + bash/file_read 自身策略；已有 `output_file`/`stdout_file` 时不二次伪持久化截断 JSON。
- `file_read` 的 byte/char continuation cursor 只按本页实际返回的源内容推进，截断提示和 JSON 元数据不计入 cursor；超长单行必须返回 `next_start_char`，不得伪造下一行。
- compact 成功后重置 MemoryLoader 缓存与相关 baseline 策略，见 Compact 报告。

## 7. 删除的旧概念

| 旧行为 | 现状 |
|--------|------|
| `history_window` 尾裁 | 已删除 |
| `load_latest_history(max_messages=)` 生产裁剪 | 已删除 |
| 每轮注入 Local SessionState | 默认不注入 |
| compact 丢最旧未摘要消息 | hierarchical 无丢失；预算失败则整次失败 |
