# 运行时上下文增量（World State）技术说明

> 更新于 2026-07-23。旧稿用「section 内容 hash 指纹」描述思路；**当前实现**以 `context/world_state.py` 的 `WorldStateSnapshot` **规范值 diff** 为准，不再依赖独立 fingerprint 表。

## 1. 问题

每轮都要把环境类信息（instructions、environment、MCP 说明、日期等）告诉模型。若：

- 原地改写 history 里旧的 context 消息 → 破坏 provider prefix cache；
- 每轮把**全部** section 再塞一条 user 消息 → 未变内容重复占 token。

因此只应追加**真正变化**的 durable section。

## 2. 当前机制

### 2.1 DynamicSectionResult（三态）

| status | 含义 | 对 baseline 的影响 |
|--------|------|-------------------|
| present | 读成功且有内容 | 可进入 diff |
| absent | 确认不存在 | 可生成 removed |
| error | 读取失败 | **保留旧 baseline**，不发 removed |

### 2.2 persistence

| 类型 | 例子 | history / compact baseline |
|------|------|---------------------------|
| persistent | environment、instructions、plan 等 | 成功回合后提交；后续比 baseline |
| request_only | knowledge、runtime_instructions、raw_environment | **仅本轮请求**，不进 durable history |

`session_state`：**默认不注入**模型（只服务 UI/审计）；需要时走独立 recovery，不每轮 diff。

### 2.3 WorldStateSnapshot.diff

- 基线：`_world_state_baseline`（从 history 里已提交的 context_update 恢复，或 empty）。
- 本轮：收集 persistent sections → `diff(baseline)` → `changed` / `removed`。
- 仅当有变化时追加一条 `<context-update>` user 消息；同名 section **以后写为准**。
- 请求成功后更新 baseline；失败不推进。

### 2.4 请求顺序（简化）

```text
稳定 system
完整 active history（含历史 context_update，append-only）
本轮 persistent 增量 context_update（可空）
本轮 request-only 块（可空，不提交 history）
当前用户消息
```

跨用户回合移除上一轮 request-only 时，允许最近动态尾部 cache miss；**共同前缀**至少覆盖 system + 该 transient 插入前的 durable history。

## 3. 与 compact 的关系

compact 安装 replacement 时：

- mid-turn：可把当前 pending world state 装回；
- 其它原因：通常清空 baseline，让下一轮完整重注入 durable sections。

## 4. 已废弃说法

- 为每个 section 维护独立 hash 指纹字典再比较（语义已由 snapshot 规范值 diff 覆盖）。
- 发送前 regex 动态删改旧 context_update。
- 把 knowledge / session_state 每轮写入 durable history。
