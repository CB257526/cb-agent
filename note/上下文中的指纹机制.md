# AgentSession 上下文增量更新机制

## 一、核心概念

### 1. ctx（上下文）是什么？

系统每轮自动注入给模型的**运行时环境信息**，不是用户说的话：

```
时间: 2026-07-14 15:30
当前目录: /home/user/myproject
CLAUDE.md: 用户喜欢用 tab 缩进，测试框架用 pytest
可用 MCP 服务器: filesystem, github
已注册技能: python-debug, git-commit
```

### 2. section 是什么？

上下文按**独立变化的维度**拆成多个具名块：

```python
context_sections = [
    ("env_info",      "时间: 15:30, Python 3.12, cwd: /home/user"),
    ("claude_memory",  "用户偏好: tab 缩进, pytest"),
    ("mcp_instructions", "MCP: filesystem, github"),
    ("skill_list",    "技能: python-debug, git-commit"),
]
# 每个 section 独立比较，只传真正变了的部分
```

### 3. 指纹是什么？

每个 section 内容的**哈希值**，用来判断"这个 section 跟上轮相比有没有变化"：

```python
context_fingerprints = {
    "env_info":         "a1b2c3d4...",  # 环境信息的哈希
    "claude_memory":    "e5f6g7h8...",  # CLAUDE.md 的哈希
    "mcp_instructions": "i9j0k1l2...",  # MCP 指令的哈希
}
```

### 4. CONTEXT_UPDATE_KIND 是什么？

消息的元数据标签，标记这条消息是"系统注入的环境信息"而非"用户/模型对话"。用于：
- **UI 展示**：过滤掉，不显示给用户
- **上下文压缩**：跳过，不进入摘要
- **跨轮恢复**：识别并从中恢复指纹基线

### 5. CONTEXT_FINGERPRINTS_KEY 是什么？

`context_update` 消息的 metadata 里的**字段名**，值就是指纹字典。让系统跨轮记住"上次告诉模型了什么"。

## 二、问题与动机

### 为什么不简单 append 就行？

每轮对话时，环境信息（时间等）会变化，需要重新告诉模型。如果每轮都**完整注入**全部上下文：

```
Round 1: [system, "完整上下文(时间15:00, 目录, CLAUDE.md, MCP...)", "帮我写函数"]
Round 2: [system, "完整上下文(时间15:05, 目录, CLAUDE.md, MCP...)", "测试一下"]
Round 3: [system, "完整上下文(时间15:10, 目录, CLAUDE.md, MCP...)", "推送到github"]
```

**问题**：每轮只有时间变了，但 CLAUDE.md、MCP、目录完全相同。每轮都传一遍完整的 → **浪费 token，且破坏 provider 端 prompt cache**。

### 理想方案：只传变化

```
Round 1: [system, "完整上下文(时间15:00, 目录, CLAUDE.md, MCP...)", "帮我写函数"]
Round 2: [system, 旧ctx, 旧对话, "仅时间变了: 15:05", "测试一下"]
Round 3: [system, 旧ctx, 旧对话, "仅时间变了: 15:10", "推送到github"]
```

**核心挑战**：Round 3 怎么知道 Round 2 已经告诉模型了什么？→ **指纹机制**

## 三、工作机制

### 消息结构设计（为 Prompt Cache 优化）

```
[0] system           ← 稳定前缀，provider 端可缓存
[1] ctx_update (旧)   ← 来自 history，上轮注入的上下文
[2] user (旧)         ← 上轮用户输入
[3] assistant (旧)    ← 上轮模型回答
[4] ctx_update (新)   ← 本轮新增，只含变化的 section
[5] user (当前)       ← 本轮用户输入
```

**关键**：[0]~[3] 连续对话时完全不变 → provider KV cache 命中，只需算 [4][5]。

### 为什么上下文用 user 消息而不是 system 消息？

OpenAI 协议中多条 system message 的行为未定义（部分 provider 会丢弃/合并/报错），所以变动上下文作为 `role=user` 的消息放到请求尾部，用 `<context-update>` 标签标明其"信息性/低优先级"语义。

### 完整流程

```
Round 1（首次对话）:
  _context_fingerprints = {}  // 空，没有上轮基线
  当前指纹 = {"env": "hash_A", "memory": "hash_B", "mcp": "hash_C"}
  diff → 全部是新的 → 完整注入 context_update
  存入 history: Message(content="<context-update>完整上下文</context-update>",
                       metadata={"kind": "context_update",
                                  "context_fingerprints": {"env": "hash_A", ...}})
  更新基线: _context_fingerprints = {"env": "hash_A", "memory": "hash_B", "mcp": "hash_C"}

Round 2（只有时间变了）:
  从 history 恢复基线: {"env": "hash_A", "memory": "hash_B", "mcp": "hash_C"}
  当前指纹 = {"env": "hash_D", "memory": "hash_B", "mcp": "hash_C"}  // hash_A ≠ hash_D
  diff → 只有 env 变了 → 只注入 "env_info: 时间15:05"
  存入 history: 新的 context_update（指纹包含全部: {"env": "hash_D", "memory": "hash_B", "mcp": "hash_C"}）
  更新基线: _context_fingerprints = {"env": "hash_D", "memory": "hash_B", "mcp": "hash_C"}

Round 3（没有任何变化）:
  从 history 恢复基线: {"env": "hash_D", "memory": "hash_B", "mcp": "hash_C"}
  当前指纹 = {"env": "hash_D", "memory": "hash_B", "mcp": "hash_C"}
  diff → 空 → 不注入任何 context_update → 零额外 token！
```

## 四、关键函数与设计决策

### `_context_fingerprints_from_history(history)`

```python
def _context_fingerprints_from_history(history):
    for message in reversed(history):       # 从后往前找
        if _message_kind(message) != CONTEXT_UPDATE_KIND:
            continue
        raw = metadata.get(CONTEXT_FINGERPRINTS_KEY)
        if isinstance(raw, dict):
            return {...}   # 找到 → 返回
        return {}          # 找到但无指纹（旧版本）→ 降级
    return {}              # 没找到 → 完整注入
```

### 为什么必须找**最近一次**的？

每次 context_update 写入的指纹都是**当时所有 section 的全量快照**，不是增量。最近一次的指纹 = **模型当前已知的全部上下文状态**。用更早的会把中间轮次已注入的内容重复注入。

### 为什么旧版本无指纹时返回 `{}` 而不是往前找？

```python
# 发现最新 context_update 没有指纹 → 说明来自旧版本
# 立即返回 {}，不继续往前找
return {}  # 降级到完整注入，自动升级到新格式
```

**设计哲学**：宁可多传一次数据（完整注入），也不能基于不完整的基线做增量更新。优化可以失败并回退，但错误不能扩散。

## 五、总结

**一句话**：用"上次告诉模型的内容的哈希（指纹）"和"现在需要告诉模型的内容"做 diff，只传变化的部分。

**核心价值**：
- **节省 token**：没变化时零额外消耗
- **最大化 prompt cache 命中**：前缀 `[system, 旧ctx, 旧对话]` 完全不变
- **自动版本升级**：旧数据无指纹 → 返回 {} → 完整注入 → 自动写入新格式指纹
