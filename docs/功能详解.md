## 记忆系统

### light：默认 Markdown 记忆

light 模式不会 import / register 旧 `MemoryTool`、`RAGTool`，不需要 embedding、向量库或 RAG env。

#### 目录结构

| 级别 | 路径 | 用途 |
|---|---|---|
| 全局 | `~/AGENT.md`、`~/USER.md`、`~/RULE.md`、`~/MEMORY.md` | Agent 人格、用户身份、全局规则、长期记忆 |
| 项目 | 当前项目链上的 `AGENT.md`、`USER.md`、`RULE.md`、`MEMORY.md`、`.cbagent/*.md`、旧 `CLAUDE.md` | 当前仓库的约定、进展、参考 |
| 短期 | `.cbagent/SHORT_TERM.md` | 当前任务进展、临时决策、近期上下文 |
| 知识库 | `~/knowledge/pages/*.md`、`~/knowledge/index.json`、`~/knowledge/graph.json` | 结构化知识页面、交叉引用 |

#### 记忆文件格式建议

```markdown
---
name: 用户偏好
description: 用户希望回答使用中文并附验证命令
type: user
scope: global
---

用户偏好：回答使用中文，必要时说明验证命令。
```

#### 工作流程

- 每轮请求时，memory section 加载三层 Markdown 记忆，并按当前问题从知识库检索相关页面
- 每轮完成后 agent 会 best-effort 把重要用户事实追加到 `~/MEMORY.md`，可复用知识沉淀为 `~/knowledge/pages/*.md`
- 模型可显式调用 `knowledge_write` / `knowledge_search` 工具
- 设置 `CBAGENT_ENABLE_FULL_MEMORY=1` 后，同一工具会额外尝试 RAG/向量索引

详细设计见：`note/cbagent上下文构建与跨会话持久记忆构建.md`、`note/cbagent知识库设计.md`

### full：旧向量记忆与 RAG

完整安装后启用：

```bash
set CBAGENT_ENABLE_FULL_MEMORY=1
python run_agent.py --memory-system full
```

full 模式注册的工具：

| 工具 | 说明 |
|---|---|
| `memory` | Episodic / Semantic / Working 三层记忆 |
| `rag` | 文档、多模态 RAG 检索 |

相关文档：`memory/rag/RAG_GUIDE.md`、`memory/storage/VECTOR_STORE_GUIDE.md`、`memory/storage/GRAPH_STORE_GUIDE.md`

### off：关闭长期记忆

```bash
python run_agent.py --memory-system off
```

off 模式不使用 Markdown 记忆，也不注册旧 `memory` / `rag`，但仍保留本地 session/history/state。

## 会话、工作记录与 compact

### 本地会话

保存在 `.cbagent/sessions/`：

| 文件 | 说明 |
|---|---|
| `index.json` | 当前 active session 指针 |
| `transcript.jsonl` | 每轮 user、final answer、工作记录、压缩 trace 审计 |
| `state.json` | rolling summary、已读文件、已改文件、最近命令、待办等 |
| `compact.json` | 最近一次 compact 快照 |
| `compactions.jsonl` | compact 审计事件 |

跨轮工具记录不会保存完整 file content 或 bash stdout，而是压缩成【工作记录】，下一轮作为普通 assistant history 进入上下文。

### 多会话

| 命令 | 说明 |
|---|---|
| `/sessions` | 列出本项目本地会话 |
| `/new` | 新建并切换到空白会话 |
| `/switch <session_id>` | 切换到指定会话 |
| `/clear` | 删除当前 active session 文件并清空内存 history |

TUI 支持 `/sessions` 面板、`/new`、`/switch <id>`。

### 手动 compact

```
/compact
```

把当前 `history + state` 压成【上下文压缩】，保留 transcript 审计。

### 自动 compact

模型 `max_tokens` 的 80% 作为安全上下文预算：

```python
CONTEXT_USAGE_RATIO = 0.8
```

超出阈值时后端自动 compact。

## 桌宠

桌宠由 cb-agent 内置 Python runtime 提供桌面浮窗、透明置顶、拖动、显示/隐藏和 agent 状态联动。不需要 Rust、Node、Tauri 或额外构建。

### 技术实现

- 使用 `pywebview` 的 Qt WebEngine 后端承载透明 Live2D WebGL 页面
- Live2D 模型通过 `pixi.js` + `easy-live2d` + Live2D Cubism Core 真实加载 `.model3.json`
- Python sidecar 使用 `pynput` 监听全局键盘/鼠标，驱动 `ParamMouseX/Y` 等参数
- 运行时日志写入 `.cbagent/logs/system/pet-runtime.log`

### 支持的宠物包类型

| 类型 | 说明 |
|---|---|
| BongoCat Live2D 目录 | 社区常见 BongoCat/Cubism 包；真实渲染 `.moc3`，默认透明背景 |
| spritesheet | AI 生成友好的动画包，含 `pet.json` 和 atlas 图片 |

### CLI / TUI 命令

| 命令 | 说明 |
|---|---|
| `/pet` 或 `/pet status` | 查看 runtime、可见性、当前宠物和活动状态 |
| `/pet install <folder>` | 安装宠物包根目录 |
| `/pet list` | 列出已安装宠物 |
| `/pet select <id>` | 选择并加载宠物 |
| `/pet uninstall <id>` | 卸载已安装宠物 |
| `/pet launch` | 启动轻量 Python runtime |
| `/pet show` / `/pet hide` | 显示或隐藏桌宠窗口 |
| `/pet quit` | 关闭 runtime |

### 首次配置

```bash
# 安装依赖（requirements.txt 已包含 qtpy / PySide6）
pip install -r requirements.txt

# 在 CLI/TUI 中
/pet launch
```

### 环境变量

```powershell
$env:CBAGENT_PET_MAX_SIZE="520"  # 自动缩放时的最大边
$env:CBAGENT_PET_SCALE="1"       # 按 Live2D 原始尺寸显示
$env:CBAGENT_PET_X="80"          # 桌宠窗口 X 坐标
$env:CBAGENT_PET_Y="80"          # 桌宠窗口 Y 坐标
```

也可以直接在桌宠窗口上滚动滚轮调整大小，设置会写入 `~/.cbagent/pet/state.json`。

### 导入外部素材

BongoCat Live2D 素材：

```
/pet install "C:\path\to\pet-folder"
/pet list
/pet launch
/pet show
```

导入前可校验：

```bash
python .\skills\hatch-bongocat-pet\scripts\validate_bongocat_pet.py "C:\path\to\pet-folder"
```

spritesheet 打包：

```bash
python .\skills\hatch-bongocat-pet\scripts\package_spritesheet_pet.py \
  --pet-id my-pet --display-name "My Pet" \
  --spritesheet "C:\path\to\atlas.png" \
  --output-dir "C:\path\to\bongocat-pets"
```

免命令导入：把宠物包目录直接放进 `.cbagent\pet\` 或 `~\.cbagent\pet\`，下次 `/pet list` 或 `/pet launch` 时自动扫描。

## MCP

项目根目录的 [mcp.json](../mcp.json) 当前包含：

| server | 说明 |
|---|---|
| `amap-maps` | 高德地图 MCP，需要 `AMAP_MAPS_API_KEY` |
| `playwright` | Playwright MCP，通过 `npx` 启动 |
| `tavily` | Tavily MCP，需要 `TAVILY_API_KEY` |
| `github` | GitHub HTTP MCP，需要 `GITHUB_PAT` |
| `fetch` | 网页抓取 MCP |
| `codegraph` | 代码分析 MCP |

启动时 `run_agent.py` 读取 `mcp.json`，把每个 MCP server 的子工具展开注册。跳过 MCP：

```bash
python run_agent.py --no-mcp
```

## Skills

Skill 是"Prompt as Capability"：用 Markdown + YAML frontmatter 写能力说明，必要时引用脚本。

### 查看可用 Skill

```
/skills
```

### Skill 设计原则

- Skill 适合多步骤工作流，而不是单个原子操作
- system prompt 只注入 Skill 名称、描述和 `SKILL.md` 路径
- 显式 `$skill` 会把正文追加到当前轮；隐式触发时模型用 `file_read` 读取 `SKILL.md`
- 可以附带脚本，统一通过 `bash` 执行，SkillManager 只做事后命中记录

相关文档：`skills/SKILLS_GUIDE.md`
