## 五大子系统

### 1. `agent/cb_agents.py` — CbAgentsLLM

OpenAI-compatible 客户端。核心方法是 `_think_with_Function_Calling`：

- `stream=True` 时按 `index` 累积 `delta.tool_calls`（name 和 arguments 都可能跨多 chunk 到达）
- 单独展示 `delta.reasoning_content` 用于 REPL 渲染思考块
- DeepSeek 思考模型依赖此分片重组逻辑

### 2. `context/builder.py` — ContextBuilder（GSSC 管道）

- **Gather** → **Select**（相关性 + 时效性 + MMR）→ **Structure**（优先级桶：Role & Policies / State / Evidence / Context）→ **Compress**（丢弃整包，不拆分 sections）
- 同步 `build()` 和异步 `abuild()`（后者用 `asyncio.gather + to_thread` 并行化记忆/RAG 检索）
- 详见 [context/README.md](../context/README.md)

### 3. `tools/` — 工具抽象层

- `tools/tool.py` 定义 `Tool` ABC；`tools/toolRegistry.py` 是注册表
- 原生工具：`tools/tools/` 下每个子类实现 `get_parameters` / `validate_parameters` / `run`
- MCP 工具：`tools/mcp_tools/mcptools_add.py` 读取 `mcp.json`，启动每个 server，展开为独立的 `MCPWrappedTool` 实例
- LLM 无法区分原生工具和 MCP 工具

### 4. `skills/` — Prompt-as-Capability

- Skill 是 Markdown + YAML frontmatter 文件，位于 `.cbagent/skills/<name>/SKILL.md`
- `SkillManager` 发现并把轻量目录注入 prompt；显式 `$skill` 只在本轮追加 body
- 脚本统一由 `bash` 执行，SkillManager 只做事后命中记录

### 5. `memory/` — 三层记忆 + 多模态 RAG

- `memory/types/`：episodic、semantic、working、perceptual 记忆类
- `memory/storage/`：可插拔后端 — 向量（`zvec` 本地 / `qdrant`），图（`sqlite` / `neo4j`）
- `memory/rag/pipeline.py`：文本/图片/音频统一管道，OCR/ASR 转换非文本后 embedding
- `memory` 工具自动路由到正确记忆类型

### 工具调用循环

`run_agent.py:AgentRunner` — `MAX_TOOL_ROUNDS = 8`。每轮：

1. 调用 `llm.think(messages, tools=registry.openai_schema)`
2. 追加 assistant 消息（含 `tool_calls`）
3. 执行所有工具调用
4. 追加每个结果为 `role="tool"` 消息
5. 重复直到模型不再返回 `tool_calls`

达到 `MAX_TOOL_ROUNDS` 是硬停止。

### Tool vs MCP vs Skill 边界

| | Tool | MCP | Skill |
|---|---|---|---|
| 是什么 | 原子 Python 函数 | 外部进程（MCP 协议） | Markdown 工作流 + 可选脚本 |
| LLM 如何使用 | OpenAI function call | OpenAI function call（包装后） | 根据 overview 读取 SKILL.md 或响应 `$skill` 显式触发，再用普通工具执行 |
| 什么时候加 | 需要新的进程内原子能力 | 复用已有的 MCP server | 需要声明式多步工作流 |

## 设计要点

### 高缓存命中率上下文设计

核心思路：**稳定前缀 = 缓存命中**。

System message 是 messages[0]（最前），如果 system message 里包含每轮变化的内容（时间、env_info、记忆等），整个前缀就变了，provider 端 KV cache 永远不命中。

拆分方案：

```
get_static_system_prompt() → messages[0].role=system
  纯确定性内容（intro/行为规则/工具使用/output 格式）
  相同入参下永远不变 ← provider 端跨轮缓存的稳定前缀

get_dynamic_context_prompt() → messages[N].role=user
  <context-update> 包装的运行时上下文
  每轮可能变化，作为低优先级 user 消息注入
```

同时有 Section 级 LRU 缓存（`context/sections/cache.py`），`OrderedDict` 实现，100 条目上限，`_MISSING` 哨兵区分"未缓存"与"缓存了 None"。`/clear` 和 `/compact` 时自动失效。

### Plan Mode 协作模式

「先计划后执行」的协作模式，两层防护确保安全：

1. **Prompt 层** — plan 模式下注入 Plan Mode 行为指令，告知模型只读约束
2. **执行层** — `PlanExecutionPolicy` 在 ToolExecutor 做服务端硬拒绝，plan 模式下只允许 `file_read`、`glob`、`grep`、`ls`、`load_image`、`knowledge_search` 等只读工具 + bash 只读命令（`ls`、`cat`、`git log` 等），写入/修改/网络/后台命令一律拒绝

工作流程：

```
用户切 Plan Mode → LLM 只读调研、编写计划 → 用户审核
  → 批准 → 自动切 execute，计划作为实施指南注入上下文
  → 拒绝 + 反馈 → LLM 修订计划重新提交
```

状态持久化在 `.cbagent/plan/` 目录，跨会话保持。TUI 和 CLI 都支持 `/plan` 命令切换模式。

### Hooks 生命周期钩子

Hook 机制在 agent 生命周期关键节点自动执行外部命令，命令可以**阻止工具执行**、**改写工具输入**或**向模型注入额外上下文**。支持 6 个事件：

| 事件 | 触发时机 | 能力 |
|---|---|---|
| `SessionStart` | 会话首个 Prompt 提交 | 注入上下文 |
| `UserPromptSubmit` | 每次提交 Prompt | 拦截输入 / 注入上下文 |
| `PreToolUse` | 工具执行前 | 阻止工具 / 改写输入 |
| `PostToolUse` | 工具成功完成后 | 注入上下文 |
| `PreCompact` | 上下文即将压缩前 | 仅通知（导出/保存） |
| `Stop` | 整轮回答收尾前 | 仅通知（生成报告/清理） |

配置位于 `.cbagent/hooks.json`，结构对齐 Claude Code。支持 matcher 模式（精确名、`|` 列表、正则），handler 通过 stdin 接收事件 JSON，exit code 和 stdout 影响主流程。无配置文件时 hooks 完全关闭，零开销。

### ContextBuilder：Section / Boundary

动态上下文顺序：

1. system instructions
2. 本地 session state
3. global/project/short-term Markdown memory
4. structured knowledge snippets from `~/knowledge/`
5. optional full memory/RAG
6. history
7. additional packets

结构化 prompt 固定为：

- `[Role & Policies]`
- `[Task]`
- `[State]`
- `[Evidence]`
- `[Context]`
- `[Output]`

详细见 `note/上下文工程架构技术报告.md`。

### 单轮 messages 与跨轮 history 分离

工具循环中的 `assistant.tool_calls`、`role=tool`、`tool_call_id` 不会跨轮恢复。跨轮只保存普通 user/assistant 文本、`【工作记录】` 和 `【上下文压缩】`。

### TUI transport

- stdout：NDJSON 事件/响应
- stdin：RPC 请求
- stderr：后端日志，写到 `.cbagent/logs/system/gateway-<timestamp>.log`

### 通讯平台 transport

QQ/NapCat 与微信 OC 都通过 `agent.platforms` 的平台无关消息层适配 EventBus 事件。`InboundMessage`、`OutboundMessage`、`PlatformEventRenderer`、`ConversationKey` 会话隔离、QQ 敏感权限和编号问答都能跨平台复用。

## 常见问题

### 启动时报 `LLM_MODEL_ID` 找不到

检查 `.env` 中的 `LLM_MODEL_ID` 是否在 [constant/llm/constant_llm.py](../constant/llm/constant_llm.py) 登记。新增模型需补 `is_tool`、`is_reasoning`、`max_tokens`、`image_ability`。

### TUI 启动后 Python 后端退出

查看日志：`.cbagent/logs/system/gateway-<timestamp>.log`。也可以指定 Python 路径：

```bash
CB_AGENT_PYTHON=/path/to/python npm start
```

### `/tools` 里没有 `memory` 和 `rag`

这是默认 light 模式的预期行为。要使用旧向量记忆/RAG：

```bash
pip install -e ".[full]"
set CBAGENT_ENABLE_FULL_MEMORY=1
python run_agent.py --memory-system full
```

### Web 搜索不可用

`my_advanced_search` 使用核心依赖里的 `requests` 直连 Tavily 或 SerpApi。配置任意一个 API Key 后重启：

```env
TAVILY_API_KEY=...
SERPAPI_API_KEY=...
```

### full RAG/Memory 依赖太重

使用默认 light 模式即可。Markdown 记忆不需要 embedding、Qdrant、Neo4j 或本地模型。

### MCP server 启动失败

检查 `mcp.json` 中 `${VAR}` 引用的环境变量是否在 `.env` 中设置。缺失的 key 会在 `load_mcp_tools` 中静默跳过。

### 流式输出异常

可能是 tool_calls 累积没有按 `index` 键值，请检查 `_think_with_Function_Calling` 方法。

### 启动时 `is_tool` KeyError

`LLM_MODEL_ID` 未在 `ConstantLLM.llm_dict` 中注册。在 [constant/llm/constant_llm.py](../constant/llm/constant_llm.py) 中补全该模型的配置。
