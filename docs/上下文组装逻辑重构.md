CbAgent 单一 Canonical History 重构计划
总体设计
删除长期存在的 messages 数组。会话唯一可变的模型上下文为 ConversationHistory。
system instructions 与 tools schema 不进入 history，作为稳定 RequestEnvelope；OpenAI adapter 发送时再生成 system message。
provider 请求由 RequestEnvelope + ConversationHistory.snapshot() 临时序列化，不维护第二套可变消息状态。
普通运行只能 append；只有正式 compact、clear 和一次性旧会话迁移可以提升 history_generation 并替换历史。
所有模型实际见过的 RAG、Skill、hook、平台上下文、后台通知和图片逻辑项都必须进入 history，不再存在 request_only 模型上下文。
world-state baseline 只是从 history 中的 snapshot/patch 推导出的缓存索引；恢复时重建，不作为第二份上下文真相。
核心接口
接口	职责
HistoryItem	不可变逻辑项，保存 item_id、turn_id、kind、role、typed content、原始 tool calls/reasoning、metadata 和 content digest
ConversationHistory	提供 append_batch()、snapshot()、replace_after_compact() 和协议校验
RequestEnvelope	保存稳定 system、冻结的 tools schema、模型配置、输出参数和整体 fingerprint
RequestSnapshot	保存 generation、last item seq、已序列化 provider payload、token 估算和 envelope fingerprint；重试必须复用同一实例
ContextFragment	用 world_state 或 turn_evidence 表示语义，不再用 persistent/request_only 决定是否进入 history
HistoryJournal	history v4 的唯一持久化真相，记录 append、compact replacement、失败边界和迁移边界

HistoryItem.content 与多模态计划共用 TextPart、ImageRefPart、ArtifactRefPart。raw base64 不写 JSONL；provider adapter 根据不可变 blob 确定性还原。
实施阶段
1. 建立不可变协议模型与 v4 Journal
将 core/message.py 升级为不可变逻辑消息，保留 provider 返回的 tool arguments 原始字符串、reasoning 和 content 类型。
新建 ConversationHistory，集中执行 item ID、digest、tool-call 配对、turn 状态和 generation 校验。
新建 history.jsonl：每行是带单调 event_seq 的 append 或 replacement 事务。写盘并 flush 成功后才能推进内存 history。
compact replacement 单行保存来源 generation/cursor、replacement items、covered/retained item IDs、摘要指标和校验和；坏尾行不得覆盖上一代有效 history。
UI transcript、session history、world-state baseline 和 Plan 面板全部成为 journal 的只读投影。
2. 一次性迁移旧会话
将现有 v3 transcript、compact、active turn 和 pending user 读取逻辑移动到独立 migrator。
首次打开旧会话时，按当前恢复规则还原一次，生成 v4 generation 基线并记录 migration_cache_boundary。
已配对 assistant/tool 原样迁移；未完成回合追加 turn_aborted，不得伪造工具结果。
新 journal 校验成功后，将旧文件改名为只读 legacy 备份；正常运行路径只读取 v4，不长期维持双读分支。
迁移完成后删除生产恢复路径中的 v2/v3 cursor、compact offset、pending/active 拼装代码。
3. 重写用户输入装配
每个用户回合先生成不可变 TurnInputBatch，固定顺序为：
world-state snapshot/patch
plan mode/state transition
runtime guidance changes
platform/hook/RAG/Skill/background/attachment evidence
real user message
TurnInputBatch 仅用于预检，不是第二套请求 history。
先估算 envelope + history + batch；需要 pre-turn compact 时先压缩旧 history，再 append batch。
batch append 并持久化成功后，才允许第一次 provider 请求。
单项注入上限 10K token；超限内容必须先成为 artifact 并注入稳定引用，无法外置则明确拒绝，不静默裁剪。
RAG 和 runtime evidence 带 query/turn/source 标识，长期保留到正式 compact，但不进入 world-state baseline。
4. 重写 Tool Loop
CbAgentsLLM.think() 改为接收 RequestSnapshot；删除可变 messages 参数。
完整 assistant 响应先原样 append 并持久化，再执行工具；不能重序列化 arguments。
每批工具必须形成完整终态。取消、拒绝、超时和异常也要生成与 call ID 配对的 tool result。
并行执行结果按模型 tool-call 顺序 append；执行检查点也写入同一 journal，不再维护 active_turn.jsonl。
load_image 追加正式 tool result 和确定性的 media bridge 逻辑项；删除 pending_images 旁路。
PreToolUse 改写只记录 requested/effective arguments，不改写历史中的 assistant call；工具结果明确说明实际执行参数。
每次采样前可追加新的后台/子代理通知，然后直接 snapshot 全量 history。
5. Provider 失败事务
rate-limit 或无任何流式输出的 transport retry 必须复用原始 RequestSnapshot，禁止重新读取 sections、tools 或重建 JSON。
明确 overflow 可触发一次正式 compact，并用新 generation 创建新 snapshot 后重试。
未知 400、鉴权和不明确的 token 文案不得自动 compact。
最终失败不回滚用户输入，而是追加模型可见的 turn_failed 边界，记录错误分类、request ID 和是否存在部分输出。
已展示的部分文本写入失败边界或不可变 artifact；不完整 tool-call JSON 不伪装成 assistant tool call。
用户取消追加 turn_aborted；下一轮模型能够区分“未回答”与普通连续追问。
6. Compact 重构
compact 直接读取 canonical history，不再接受 source_history、summary_source 或 in-flight 拼接参数。
按 turn ID 分成 summarized_prefix、retained_tail 和 active_turn_items。
只摘要真正被淘汰的 summarized_prefix；最近完整回合和当前活动回合不进入摘要，也不被重复概括。
保留预算继续采用 clamp(soft_limit / 10, 16K, 128K)，并扣除 envelope、摘要输出预留、最新 world-state snapshot、当前 batch/active turn。
只能按完整 user/tool 协议回合缩减 retained tail；禁止拆散 assistant.tool_calls 与 tool messages。
pre-turn replacement 为 retained_tail + summary，随后 append 最新 snapshot/evidence/user。
mid-turn 只在完整采样及工具批次结束后触发，replacement 为 retained_tail + latest full world-state + active_turn_items + summary。
如果去掉全部 retained tail 后仍无法让 mid-turn 请求回到 soft limit，compact 不安装 replacement，结束当前回合并追加明确失败边界。
hierarchical map/reduce 仅处理 summarized prefix，保留现有 8 chunks、12 requests、4 倍 hard-limit prompt 和 64K completion 总上限；超限必须失败且 history 不变。
compact 成功后原子写 replacement、递增 generation、重置 provider cursor和 world-state 派生 baseline，再继续采样。
7. Plan Mode 顺序
/plan、重新进入、拒绝、批准和退出都立即追加一次结构化 mode transition；不再每轮重复生成 Plan system/context 文本。
tools schema 在用户回合开始时按 mode 冻结，整个 tool loop 不变化；模式切换属于显式 envelope/cache boundary。
<proposed_plan> 所在 assistant 原文完整进入 history，UI 解析只影响显示，不能修改 canonical 内容。
Plan 文件继续保存不可变 revision；PlanStateStore 变成 history 的 artifact/界面投影。
compact 后通过 latest world-state 恢复 mode、plan path、revision、status 和 hash；计划正文超出注入上限时要求模型通过只读工具读取 artifact。

turn_prefix_messages

_extract_protocol_messages

agent/session.py 只保留 orchestration；history/journal、请求快照、context fragment 和 compact 分别下沉到独立模块，避免继续扩大当前 3K 行文件。新增注释严格使用中文。
兼容与可观测性
Gateway 的 history、context_window、usage 和 Plan payload 保持向后兼容；可选新增 history_generation、last_item_seq、envelope_fingerprint 和 cache_reset_reason。
system、tools、模型、Plan mode 或 compact 变化都记录明确 cache boundary；只有 envelope fingerprint 相同时才要求跨请求精确前缀连续。
model downshift 继续使用旧模型先 compact，再切换目标配置；多模态能力变化复用 ImageRef 重构计划的 adapter 规则。
Context Footer 始终按真实 RequestSnapshot 统计 system、tools、history 和视觉成本，不再估算另一套“下一请求消息”。
测试与验收
对每次 provider 调用保存稳定序列化快照；同 generation、同 envelope 下，断言请求 N 的模型输入是请求 N+1 的精确前缀。
覆盖普通工具循环、下一用户回合、RAG、Skill、hooks、平台上下文、后台通知、直接图片、load_image、Plan、重试、恢复和模型切换。
覆盖 pre-turn/mid-turn/manual/downshift compact，验证摘要仅覆盖淘汰前缀、active turn 字节不变、summary 顺序正确且无孤儿 tool。
覆盖 128K、400K、1M 窗口及 active turn 超限；验证动态 retained budget 和失败不替换规则。
在 journal append、assistant 落盘、工具执行、tool result、compact replacement 各边界模拟崩溃，恢复后的下一请求必须与崩溃前已确认的 canonical history 协议等价。
覆盖 v3 一次性迁移、坏 JSON 尾行、重复 event、compact 写一半和迁移重入幂等。
删除所有仍依赖 commit_offset、request_only 或“回合结束再反推 history”的测试。
验证命令：聚焦测试后运行 ../venv/bin/python -m pytest、ui-otui 下 bun test、git diff --check；环境依赖失败与代码回归分别报告。
完成标准
生产代码中只有 ConversationHistory 持有模型可见的可变对话序列。
除 system/tools envelope 外，不存在“模型看见但 canonical history 不记录”的内容。
非 compact 路径没有任何旧 item 改写、删除、类型替换或重新排序。
正式 compact 只造成一次可观测 generation 变化，失败时 generation 和 history 完全不变。
会话重启、provider retry 和跨用户回合不再通过“语义等价重建”修改旧请求前缀。
